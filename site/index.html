Retrieval got worse. Nothing paged. Watch for it.

A CLI and small service that probes a vector store for query latency and tracks embedding drift between snapshots of a fixed query set. It alerts a Slack-shaped webhook when either crosses a threshold twice in a row.

Change the embedder, watch the distance move

Take a snapshot of a fixed query set, change the embedder, take another, and compare. The real hashing embedder, cosine distance, threshold check and Slack-shaped alert payload run in your browser. The embedders are simulated stand-ins for a model version bump, exactly as in the repo's own demo. They are not semantic models.

Each cycle uses the same two snapshots here, so a breach repeats until you change a setting. In the real tool every cycle re-probes the live store, so one noisy sample does not page anyone.

How it works

A RAG pipeline can look healthy while retrieval quietly gets worse. This watches the two signals that predict it.

1

Probe latency

Run a fixed query set against a pgvector store several times and report p50, p95 and p99. A p95 climbing as the index grows usually means a sequential scan.

2

Snapshot and compare

Embed the same queries on a schedule and compare snapshots with cosine distance. A step change in distance after an unannounced model bump shows up here.

3

Alert on a streak

A threshold must be breached on consecutive cycles before it posts a Slack-shaped payload to a webhook, so a single outlier does not escalate.

Run it against a real store

Python 3.12, Docker for Postgres with pgvector.

docker compose up -d
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export VECTOR_DRIFT_WATCH_DATABASE_URL="postgresql://vdw:vdw@localhost:5432/vdw"

python -m vector_drift_watch.cli init-schema
python -m vector_drift_watch.cli ingest
python -m vector_drift_watch.cli probe --repeats 30
python -m vector_drift_watch.cli snapshot snapshots/baseline.json
python -m vector_drift_watch.cli snapshot snapshots/now.json
python -m vector_drift_watch.cli drift snapshots/baseline.json snapshots/now.json
python -m vector_drift_watch.cli watch --webhook-url http://127.0.0.1:8787 --cycles 1

Swap the hashing embedder for a real model by implementing the same embed(text) protocol.

What this does not do
  • This page does not measure latency. That needs a live vector store, so only the repo's CLI does it.
  • The hashing embedder is deterministic and not semantic. Distances here show the math working, not how a real model drifts.
  • Thresholds are plain constants, not tuned against production traffic.
  • The Slack payload is the right shape. The repo's demo posts it to a local mock receiver.
